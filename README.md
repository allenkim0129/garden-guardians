# 정원 수비대

초등학교 고학년을 위한 **1인용 가로 화면 터치 디펜스 게임**입니다. 햇빛을 모아 식물을 배치하고, 조합과 방어선으로 오른쪽에서 오는 좀비들을 막습니다. 잔혹한 표현은 사용하지 않습니다.

**게임 주소:** https://allenkim0129.github.io/garden-guardians/

**공개 소스:** https://github.com/allenkim0129/garden-guardians

- 식물 5종, 좀비 4종, 순서대로 열리는 정원 10개
- 한국어 안내, 터치·마우스 조작, 정지·재시작·이어서 하기
- 기기 내 자동 저장, 최고 별 기록, 켜고 끄는 효과음
- 홈 화면 설치와 오프라인 플레이를 지원하는 PWA
- 승인된 생성 이미지의 프레임 애니메이션, 직접 그린 Canvas 그림, 직접 합성한 효과음을 사용합니다. 기존 게임의 아트·이름·음원 파일은 사용하지 않습니다.
- 광고, 계정, 분석 SDK, 서버 저장, 런타임 CDN·원격 폰트·외부 이미지가 없습니다.

## 컴퓨터에서 바로 실행하기

Node.js 22 이상을 권장합니다. 런타임 패키지 설치나 빌드는 필요 없습니다.

```powershell
cd .\garden-guardians
npm start
```

브라우저에서 **http://127.0.0.1:4173** 을 엽니다. 세로 화면에서는 가로 회전 안내가 표시됩니다. `index.html`을 파일 탐색기에서 직접 여는 `file://` 실행은 서비스 워커와 ES 모듈 때문에 지원하지 않습니다.

다른 로컬 포트:

```powershell
node scripts\server.mjs --port 4175
```

로컬 서버는 기본적으로 이 컴퓨터에서만 접근할 수 있도록 `127.0.0.1`에 바인딩합니다. 종료하려면 실행한 터미널에서 `Ctrl+C`를 누릅니다.

## 놀이 방법

1. **햇빛 모으기**: 노란 햇빛을 누르면 25를 얻습니다. 놓친 햇빛도 8초 후 자동으로 모입니다.
2. **식물 배치**: 왼쪽 식물을 고른 뒤 빈 정원 칸을 누릅니다. **배치 성공 후에는 자동으로 선택이 해제**됩니다. 선택한 카드를 다시 눌러도 선택이 해제되며, 보드에 이미 심은 식물은 제거되지 않습니다. 공격은 같은 줄의 오른쪽으로 나갑니다.
3. **정원 지키기**: 세 번의 무리를 전부 막으면 승리합니다. 좀비가 왼쪽 끝을 통과하면 하트 하나를 잃고, 하트가 모두 없어지면 다시 도전합니다.

게임 시작·재시작·이어서 하기에서는 아무 식물도 선택하지 않습니다. 선택이 없으면 땅을 눌러도 심지 않으며, 햇빛 탭은 **수집만** 합니다. 햇빛이 자동 수집되어 누르는 도중 사라지더라도 같은 포인터 동작으로 아래 땅에 식물이 심어지지 않도록 보호합니다. 배치 실패 시에는 선택을 유지해 다른 칸을 고를 수 있습니다.

| 처음 사용할 정원 | 식물 | 햇빛 | 하는 일 |
|---:|---|---:|---|
| 1 | 콩별이 | 125 | 같은 줄 앞쪽으로 완두콩 공격 |
| 1 | 햇살봉 | 50 | 처음 6초 후, 이후 8초마다 햇빛 25 생성 |
| 2 | 도토리벽 | 75 | 튼튼한 체력으로 좀비를 붙잡음 |
| 3 | 서리초 | 125 | 얼음 결정 공격과 함께 3초 동안 이동 속도 감소 |
| 4 | 방울폭탄 | 125 | 심은 뒤 1초 후 주변과 이웃 줄에 범위 공격 |

**콩별이와 햇살봉은 1단계부터 기본 해금**되어 함께 사용할 수 있습니다. **1단계 최초 클리어로 도토리벽(2단계부터 사용), 2단계 최초 클리어로 서리초(3단계부터 사용), 3단계 최초 클리어로 방울폭탄(4단계부터 사용)**을 얻습니다. 이후 다섯 종류를 조합합니다. 최초 획득 화면에는 새 식물 그림·이름·능력·햇빛 비용·사용 가능한 정원을 표시하며, 이미 깬 정원을 다시 깨면 최초 획득 안내를 반복하지 않습니다.

**사용 가능한 식물은 플레이 중인 정원 번호 기준**입니다. 예를 들어 10단계까지 열었어도 1단계 재도전에서는 콩별이와 햇살봉을 사용할 수 있습니다. 새 게임·재시작·이전 정원 재도전·기존 저장 이어하기 모두 같은 규칙을 적용합니다. 잠긴 카드와 정원 선택 화면에도 같은 해금 위치를 표시합니다.

잠옷좀비는 기본형, 젤리좀비는 튼튼한 느림보, 롤러좀비는 빠른 유형, 우산좀비는 추위에 강한 유형입니다. 처음부터 햇살봉으로 자원을 확보하고, 후반에는 도토리벽·서리초·방울폭탄을 함께 활용해 보세요.

**삽**을 누르고 식물을 선택하면 제거하고 가격의 절반을 돌려줍니다(소수점 버림). 삽 모드 진입 시 식물 선택도 해제합니다. 심은 식물 종류마다 다시 심기까지 짧은 대기 시간이 있습니다. 남은 하트 수가 별 기록이 되며, 이미 얻은 더 좋은 기록은 유지됩니다. 한 판은 혼합 전략 자동 검증 기준 약 **76~130초**입니다.

### 난이도 조정

| 항목 | 이전 | 현재 |
|---|---:|---:|
| 콩별이 비용 | 100 | 125 |
| 콩별이 1발 피해 | 22 | 18 |
| 콩별이 발사 간격 | 1.25초 | 1.6초 |
| 콩별이 평균 초당 피해 | 17.6 | 11.25 (약 36% 감소) |
| 콩별이 다시 심기 대기 | 3초 | 6초 |
| 젤리좀비 체력 / 속도 | 300 / 12 | 340 / 13 |
| 롤러좀비 체력 / 속도 | 85 / 29 | 95 / 31 |

좀비 속도 단위는 게임 좌표/초입니다. 기본 좀비와 스테이지별 등장 수·등장 간격은 그대로 두어 초반 학습 난이도를 과도하게 높이지 않았습니다.

`tests\helpers\strategy.mjs`의 동일한 판단 규칙(최대 초당 1회 배치, 실제 비용·쿨다운 준수)으로 밸런스 변경 전후를 비교했습니다. ‘콩별이 중심’은 공격 식물을 콩별이만 사용하고, 햇살봉도 함께 사용하는 전략입니다. ‘혼합’은 가까운 적에 도토리벽, 느리게 할 서리초, 밀집한 적에 방울폭탄을 사용합니다.

| 비교 전략 | 변경 전 | 변경 후 |
|---|---|---|
| 콩별이 중심 | 10개 모두 하트 3개, 식물 손실 0 | 9개 통과, 8·9단계 하트 2개, 10단계 패배 |
| 혼합 | 10개 모두 하트 3개 | 새 해금 규칙으로 10개 모두 하트 3개 |

위 표는 최초 밸런스 개정 전후의 비교입니다. 당시 혼합 전략의 식물 손실은 합계 2개에서 20개로 늘었습니다. 현재의 앞당긴 해금 순서에서는 혼합 전략으로 10개 정원 모두 하트 3개를 유지하고 식물 손실은 합계 21개입니다. 이는 정해진 전략의 회귀 검사이며, 모든 콩별이 전략의 불가능성이나 실제 어린이 플레이 난이도를 보장하는 것은 아닙니다.

햇살봉 기본 해금·보상 순서·애니메이션 수정에서는 비용·공격력·쿨다운·좀비 능력치·등장 규칙을 바꾸지 않았습니다. 현재 혼합 전략의 1단계는 75.7초, 3단계는 102.0초이며 가장 긴 정원은 129.4초입니다. 승인된 새 해금 순서를 변경 전후 엔진에 동일하게 적용한 비교에서는 전략 2종×정원 10개의 전투 상태·자원·배치 시점이 모두 일치하여 시각 변경 자체의 전투 영향을 확인했습니다.

### 현재 그래픽의 범위

사용자가 승인한 만화풍 생성 원화를 바탕으로 **식물 5종과 좀비 4종 전체를 프레임 애니메이션**으로 적용했습니다. 캐릭터마다 4열×3행, 총 **9종 108프레임**을 사용합니다.

| 캐릭터 | 1행 | 2행 | 3행 |
|---|---|---|---|
| 콩별이 | 대기 | 발사 준비·압축·발사·복귀 | 피격 |
| 햇살봉 | 대기 | 햇빛 생성 | 피격 |
| 도토리벽 | 대기 | 피격 방어 | 체력 35% 이하 균열 |
| 서리초 | 대기 | 발사 준비·발사·복귀 | 피격 |
| 방울폭탄 | 대기 | 폭발 준비 | 폭발·흩어지는 잎 |
| 잠옷·젤리·롤러·우산좀비 | 이동 | 공격 | 쓰러짐 |

콩별이·서리초의 발사와 햇살봉의 생성 프레임을 실제 생성 시점에 맞췄습니다. 새 적이 갑자기 나타나면 애니메이션을 기다리느라 발사를 늦추지 않습니다. 연속 피격도 매 틱 처음으로 되감지 않습니다. 죽은 좀비는 즉시 전투에서 제거하고 0.88초의 쓰러짐 효과만 별도로 표시하므로 추가 공격이나 승리 지연이 없습니다. 방울폭탄은 기존처럼 1초 뒤 한 번만 피해를 주고 제거되며, 이후 폭발 그림만 별도로 재생합니다. 일시 정지·화면 회전·백그라운드에서는 재생도 멈추며, 진행 중인 발사·생성·피격·공격 시점은 저장하고 복원합니다. 사망·폭발의 일회성 효과는 저장하지 않습니다.

게임 보드, 식물 카드, 시작·도움말·획득 화면과 앱 아이콘에 같은 새 아트를 사용합니다. 기존 캐릭터 벡터 시안은 제거했습니다. 과도한 공포나 잔혹 표현은 넣지 않았습니다.

완두콩은 초록색 유기적 형태와 명암·하이라이트, 서리초의 발사체는 청백색 얼음 결정으로 그립니다. 콩깍지와 얼음꽃에 맞춘 시각 원점만 보정하며 실제 충돌 좌표·피해·속도·발사 간격·저장 형식은 유지합니다. 햇살봉은 황금빛 햇빛, 방울폭탄은 주황 폭발과 잎 조각을 사용하고 도토리벽에는 공격을 추가하지 않습니다.

하늘에서 떨어지는 햇빛과 햇살봉이 만든 햇빛 모두 밝은 코어·가장자리 명암·하이라이트·태양 빛살을 사용합니다. 빛살이 천천히 회전하고 광채가 부드럽게 변하며 빠른 점멸은 없습니다. 광채 레이어는 재사용하고 게임 시간으로 움직여 정지·백그라운드 전환 때 함께 멈춥니다. 기존 48px 터치 타깃, 햇빛 25, 8초 자동 수집과 오배치 방지는 그대로입니다.

원본 RGBA 시트는 `art-source`에 보관하고, 게임에는 정렬·축소한 `assets\sprites`의 PNG 9장만 사용합니다. 각 1280×672픽셀, 합계 약 4302 KiB입니다. 실제 알파를 사용하고 크로마키 처리는 하지 않았습니다. 매우 약한 반투명 잔여색을 정리한 뒤 기존 콩별이·잠옷좀비에는 0.66, 새 7종에는 0.61의 고정 배율을 적용하고 뿌리·발 접지점을 정렬했습니다. 공격·쓰러짐의 크기 변화는 유지하며 프레임마다 제각각 확대하지 않습니다. 원본의 실제 빈 영역으로 행별 행·열 경계를 정해 발·스케이트·우산 잘림을 방지하고, 햇살봉·방울폭탄의 방향이 뒤집힌 대기 그림은 반전해 맞췄습니다.

프레임 연결로 인한 전투 규칙 변경은 없었습니다. 프레임 적용 당시 직전 엔진과 동일한 전략 2종×정원 10개를 실행하여 최종 전투 상태·자원·배치 시점이 모두 일치함을 확인했습니다. 생성된 4프레임 시트의 움직임을 사용하는 방식이며, 손으로 보정한 다프레임 애니메이션과 같은 유연함을 보장하지는 않습니다.

## 아이폰·아이패드에 설치하기

공개 게임 주소를 다른 기기의 Safari에서 열 수 있습니다. 로그인이나 앱스토어 설치는 필요 없습니다. GitHub Pages의 HTTPS를 사용하며 별도 유료 호스팅이나 도메인은 필요 없습니다.

로컬 `127.0.0.1`과 공개 주소는 서로 다른 저장 공간입니다. **기존 로컬 진행은 공개 주소로 자동 이동하지 않습니다.** 기존 로컬 기록을 지우지는 않으며 공개 주소에서는 새로 시작합니다.

### 1. HTTPS 주소 준비

일반 정적 웹 호스팅에 다음 명령으로 만든 **`dist` 폴더의 내용만** 올리면 됩니다. 별도 API나 데이터베이스, Node.js 서버 운영은 필요 없습니다.

```powershell
npm run build
```

`dist`에는 HTML, CSS, JavaScript, 매니페스트, 서비스 워커, PNG 아이콘과 가공된 캐릭터 프레임 시트만 담깁니다. `art-source`, `node_modules`, 테스트 코드, 개발 서버를 웹사이트에 배포하지 마세요. 공개 저장소의 `main`에 푸시하면 `.github/workflows/pages.yml`이 단위 검사와 정적 빌드를 수행하고 `dist`만 GitHub Pages에 배포합니다.

배포 조건:

- 신뢰할 수 있는 인증서의 **HTTPS** 주소여야 합니다.
- 주소의 루트 또는 하위 폴더에 **파일 구조 그대로** 배포합니다. 하위 폴더 주소는 끝에 `/`를 붙입니다.
- `.js`는 JavaScript, `.webmanifest`는 `application/manifest+json`, `.png`는 `image/png`로 제공합니다.
- `sw.js`는 리다이렉트·로그인 화면 없이 제공하고, `Cache-Control: no-cache`를 권장합니다.
- 런타임 파일을 누락하지 마세요. 하나라도 저장 실패하면 ‘오프라인 준비 완료’를 표시하지 않습니다.
- 로컬 컴퓨터의 `localhost`·`127.0.0.1`은 **아이폰에서 이 컴퓨터를 가리키지 않습니다**. LAN의 일반 HTTP 주소로 여는 것만으로는 iOS 오프라인 설치를 검증할 수 없습니다.
- 개인용으로 제한하고 싶다면 호스팅 접근 정책도 별도로 검토하세요. 게임 자체는 로그인이나 온라인 DRM을 포함하지 않습니다.

### 2. Safari 홈 화면에 추가

1. 아이폰·아이패드의 Safari에서 배포한 HTTPS 주소를 엽니다.
2. 기기를 가로로 돌리고 처음 화면 아래 **‘오프라인 준비 완료 · 이 기기에 저장됨’**을 확인합니다.
3. Safari **공유 → 홈 화면에 추가 → 추가**를 누릅니다. ‘웹 앱으로 열기’ 옵션이 보이면 켭니다.
4. 홈 화면의 ‘정원 수비대’ 아이콘으로 실행합니다. **그 창에서도 온라인 상태로 ‘오프라인 준비 완료’를 다시 확인**합니다.
5. 비행기 모드로 바꾸고 게임을 완전히 닫았다가 홈 화면 아이콘으로 다시 엽니다. 시작과 이어서 하기가 되는지 확인합니다.

Safari와 홈 화면 웹 앱은 OS 버전에 따라 저장 공간을 다르게 취급할 수 있습니다. 설치 전 Safari 진행 기록이 홈 화면 앱으로 옮겨진다고 보장하지 않습니다. 홈 화면 앱 안에서 처음부터 플레이하는 것을 권장합니다.

대상은 최신 iOS/iPadOS Safari이며, 사용 API 기준 **iOS/iPadOS 16.4 이상을 권장**합니다. 오래된 브라우저 지원을 위한 폴리필은 넣지 않았습니다. 설치된 앱에서도 iOS가 화면 방향 잠금을 강제할 수 있어 게임에서 세로 회전 안내를 별도로 표시합니다.

## 저장과 오프라인 동작

- 진행 데이터: `localStorage`의 `garden-guardians-save-v1`
- 열린 정원·최고 별·소리·안내 설정과 **진행 중인 판 1개**를 저장합니다.
- 진행 중 약 3초마다, 심기·삽 사용·일시 정지·결과 처리·페이지 이탈 시 저장합니다.
- 강제 종료 직전에는 마지막 약 3초의 진행이 저장되지 않을 수 있습니다.
- 다른 앱으로 이동하거나 세로로 회전하면 자동 정지합니다. 돌아와서 **계속하기**를 눌러야 재개됩니다. 오프라인 동안 게임이 혼자 진행되지는 않습니다.
- 새 정원을 시작하면 진행 중인 판만 바뀝니다. 열린 정원과 최고 별은 유지됩니다.
- 구버전 저장 키와 진행 데이터는 유지합니다. 구버전 진행 중 판은 새 밸런스(`rulesVersion: 2`)로 이관하고 기존 별·해금·이미 심은 식물은 보존합니다. 구버전에서 먼저 심은 잠긴 식물도 그 판에서는 남지만 새로 추가할 수 없으며, 안내를 표시합니다. 재시작하면 해당 정원의 정상 해금 구성이 적용됩니다. 날아가던 구버전 별콩도 새 피해량으로 이관합니다.
- 햇살봉 기본 해금과 앞당긴 해금 단계는 저장 초기화나 새 판 시작 없이 적용됩니다. 기존 1단계 저장에서도 햇살봉, 2단계에서 도토리벽, 3단계에서 서리초, 4단계에서 방울폭탄을 바로 추가로 심을 수 있습니다. 별·열린 정원·보유 햇빛·기존 쿨다운 등 진행 상태는 그대로 유지합니다.
- 저장 오류나 손상된 데이터는 화면에 안내하고, 오류를 숨기지 않습니다. 저장이 차단된 상태에서도 현재 창에서 플레이할 수 있지만 재접속 복원은 보장되지 않습니다.
- 서비스 워커는 필수 자원을 **일괄 저장**한 뒤 준비 완료를 표시합니다. 누락 시 온라인에서 **다시 저장** 버튼으로 복구할 수 있습니다.
- 캐릭터 시트 9장도 모두 필수 캐시 대상입니다. 그림을 불러오지 못하면 게임 시작을 막고 오류와 **그림 다시 불러오기** 버튼을 표시합니다. 구형 도형으로 몰래 대체하지 않습니다.
- 기기 간 자동 동기화는 없습니다. Safari 사이트 데이터 삭제, 비공개 브라우징, 앱 제거, OS 저장 공간 정리로 기록이나 캐시가 사라질 수 있습니다. 오프라인 보존은 OS 정책을 넘어 보장할 수 없습니다.
- 같은 기기에서는 한 창에서 플레이하는 것을 권장합니다. 여러 창이 동시에 진행 데이터를 수정하는 것은 지원하지 않습니다.

### 업데이트 배포

현재 오프라인 캐시는 `v7`이며 처음 화면 아래에 **화면 v7**을 표시합니다. 런타임 파일이 바뀌면 `sw.js`의 캐시 버전(`CACHE`)과 `index.html`의 화면 버전을 함께 바꾼 뒤 전체 `dist`를 배포하세요.

새 버전이 모두 저장되면 처음 화면과 일시 정지 메뉴에 **저장하고 업데이트** 버튼이 나타납니다. 누르면 진행을 저장하고 새 서비스 워커를 활성화한 다음 새로고침합니다. 저장에 실패하면 업데이트를 중단합니다. **플레이 중이나 다른 탭을 강제로 새로고침하지 않습니다.** 이미 내려받은 업데이트는 오프라인에서도 적용할 수 있습니다. 다른 탭이 먼저 업데이트했다면 이 탭에서도 버튼을 눌러 새 화면을 불러옵니다.

**v5/v6에서 처음 전환할 때:** 이 버전에는 업데이트 버튼이 없습니다. 단순 새로고침은 기존 서비스 워커 때문에 구버전을 다시 표시할 수 있습니다. 온라인에서 같은 주소의 게임 탭과 설치 앱 창을 모두 닫고 다시 열어 주세요. 사이트 데이터나 저장을 삭제할 필요가 없습니다. 새 업데이트를 다운로드하려면 온라인 연결이 필요하며 저장 스키마가 바뀌면 별도 마이그레이션이 필요합니다.

## 개발과 자동 검증

```powershell
# 게임 규칙·저장·프레임 상태·모든 스테이지 통과 검사 (외부 패키지 불필요)
npm test

# 브라우저 자동화 도구 준비
npm ci
npx playwright install chromium webkit

# Chromium + WebKit 터치·저장·오프라인 검사
npm run test:browser

# 배포 파일 만들기
npm run build
```

Playwright가 로컬 서버를 자동으로 시작합니다. 이미 `npm start`로 실행했다면 그 서버를 재사용합니다. 의존성 다운로드와 브라우저 설치에는 개발 시 인터넷이 필요하지만, 게임 실행에는 필요 없습니다.

그림 합성은 `src\art.js`, 프레임 선택·로딩은 `src\sprites.js`, 규칙·정원 구성은 `src\engine.js`, 화면·입력·수명 주기는 `src\app.js`에 있습니다. 앱 아이콘을 PNG로 다시 만들려면 로컬 서버가 실행 중인 상태에서 `npm run icons`를 사용합니다. 아이콘 생성에도 외부 이미지 서비스는 사용하지 않습니다.

원본 시트에서 게임 자산을 다시 가공할 때만 Python 3과 Pillow가 필요합니다. 일반 게임 실행·빌드에는 필요 없습니다. 원본 작업 이미지가 있는 로컬 `art-source`는 공개 저장소에서 제외했습니다. 아래 가공 명령은 해당 원본을 별도로 보유한 개발용 환경에서만 실행합니다.

```powershell
python -m pip install Pillow
python scripts\prepare-sprites.py
npm run icons
npm run build
```

가공 스크립트는 셀 경계의 잘림을 검사하고 정렬 근거를 `assets\sprites\alignment.json`에 남깁니다. 새 원화로 바꾸면 이 스크립트의 행 경계·뿌리/발 좌표도 원화에 맞게 확인해야 합니다. 외부 이미지 생성 서비스에 런타임 요청을 보내지 않습니다.

### 검증 범위와 한계

`npm test` **38개 통과**, 기존 Chromium·WebKit 브라우저 검사 **45개 통과·1개 도구 제한으로 제외**, 업데이트 전용 검사 **8개 통과**를 확인했습니다. 첫 시작 두 식물, 재시작·재도전·기존 저장, 1~3단계 최초 보상과 중복 방지, 앞당긴 해금, v7 캐시 전환을 포함합니다. 구버전 열린 탭의 대기 상태, 다중 탭의 명시적 업데이트, 진행 보존, 오프라인 적용과 저장·자산 다운로드 실패도 검사합니다. 10개 정원 모두 현재 해금 구성과 실제 게임 규칙의 혼합 전략으로 하트 3개를 유지하며 통과했습니다.

배포 파일은 `npm run build`로 **23개(약 4.62 MiB)**를 만듭니다. 브라우저 검사는 선택 없음·배치 후 해제·카드 토글·햇빛 탭 및 자동 수집 중 오배치 방지·1~10단계 해금·이전 저장 이관까지 포함합니다. 568×320부터 1180×820까지 6가지 가로 화면에서 게임 칸·식물 선택·게임 상단 버튼의 터치 영역이 각각 최소 44×44 CSS 픽셀이고 화면 밖으로 벗어나지 않는지 검사했습니다. 작은 가로 화면의 최초 획득 카드도 그림·능력·비용이 버튼에 가려지지 않고 진행 버튼에 접근할 수 있는지 검사했습니다.

추가로 108개 프레임의 픽셀 차이·투명 테두리·접지 정렬, 실제 Canvas의 이동·발사·생성·피격·방어·균열·폭발·공격·쓰러짐 프레임 사용, 정지 중 화면 불변, 화면 회전·저장 복구, 이미지 누락 오류·재시도를 검사했습니다. 완두콩·얼음의 구분과 전투 좌표 불변, 햇빛 광채 변화·정지·수집도 검사했습니다. 667×375와 1024×768 실제 게임 화면을 캡처하고 약 13초의 상태 확인용 전투 장면을 녹화했습니다. 잔디 배경에 합성해 검은 사각형·색 번짐·셀 잘림과 접지 위치를 확인했습니다.

자동 검증은 비용·쿨다운·공격·방어·서리·폭탄·햇빛 수집, 승패·다음 정원·재시작, 저장 복원·손상·저장 차단, 세로 회전, 캐시 누락·복구, 네트워크 차단 후 새로고침·새 창 실행을 포함합니다. 모든 정원은 자원이나 적 능력치를 바꾸지 않는 간단한 자동 전략으로 끝까지 통과하는지 검사합니다.

오프라인 검증에서는 테스트 전용 서버를 **실제로 종료**하고, 하위 폴더 주소에서 Chromium·WebKit의 새로고침과 새 창 실행을 확인합니다. Chromium은 네트워크 오프라인 설정까지 켠 상태에서 **브라우저 프로세스를 종료하고 같은 프로필로 재실행**하는 검사도 수행합니다. Windows Playwright WebKit은 네트워크 오프라인 에뮬레이션에서 내부 오류가 발생하고, 영구 프로필에서는 CacheStorage 쓰기가 비어 있는 현상이 재현되어 프로세스 재시작 검사는 명시적으로 건너뜁니다. WebKit에서 캐시 준비 실패를 성공으로 처리하거나 테스트를 느슨하게 바꾸지는 않았습니다.

**Windows의 Chromium 및 Playwright WebKit 검증은 실제 iPhone/iPad Safari·홈 화면 앱 검증을 대신하지 않습니다.** 실제 기기를 연결해 검증하지 않았습니다. 백그라운드 전환 자동 검사는 페이지 수명 주기 이벤트를 재현한 것이며, 실제 iOS 앱 전환·메모리 회수·잠금 화면·오디오 하드웨어 동작은 실기기에서 최종 확인해야 합니다.

실기기 최종 확인 항목: 작은 아이폰의 Safari 도구막대·노치 안전 영역, 아이패드 화면 배치, 홈 화면 설치 후 비행기 모드 재실행, 3초 자동 저장과 이어서 하기, 효과음 켜기·끄기, 다른 앱이나 잠금 화면에서 돌아온 뒤 일시 정지 상태, 세로 회전과 화면 회전 잠금.
