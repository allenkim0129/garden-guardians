# 정원 수비대

초등학교 고학년을 위한 **1인용 가로 화면 터치 디펜스 게임**입니다. 햇빛을 모아 식물을 배치하고, 조합과 방어선으로 오른쪽에서 오는 좀비들을 막습니다. 잔혹한 표현은 사용하지 않습니다.

**게임 주소:** https://allenkim0129.github.io/garden-guardians/

**공개 소스:** https://github.com/allenkim0129/garden-guardians

- 식물 10종, 좀비 4종, 순서대로 열리는 정원 10개
- 한국어·영어 전환, 터치·마우스 조작, 정지·재시작·이어서 하기
- 기기 내 자동 저장, 최고 별 기록, 켜고 끄는 효과음
- 홈 화면 설치와 오프라인 플레이를 지원하는 PWA
- 승인된 생성 이미지의 프레임 애니메이션, 직접 그린 Canvas 그림, 직접 합성한 효과음을 사용합니다. 기존 게임의 아트·이름·음원 파일은 사용하지 않습니다.
- 광고, 계정, 분석 SDK, 서버 저장, 런타임 CDN·원격 폰트·외부 이미지가 없습니다.

## 컴퓨터에서 바로 실행하기

Node.js 22 이상을 권장합니다. 런타임 패키지 설치나 빌드는 필요 없습니다.

```powershell
cd .\garden-guardians
npm start
```

브라우저에서 **http://127.0.0.1:4173** 을 엽니다. 세로 화면에서도 게임 UI가 자동으로 90도 돌아가 가로형으로 표시됩니다. `index.html`을 파일 탐색기에서 직접 여는 `file://` 실행은 서비스 워커와 ES 모듈 때문에 지원하지 않습니다.

다른 로컬 포트:

```powershell
node scripts\server.mjs --port 4175
```

로컬 서버는 기본적으로 이 컴퓨터에서만 접근할 수 있도록 `127.0.0.1`에 바인딩합니다. 종료하려면 실행한 터미널에서 `Ctrl+C`를 누릅니다.

## 놀이 방법

처음 화면 오른쪽 위, 게임 상단, 안내 창 상단의 **한국어 / English** 버튼으로 언어를 바꿉니다. 기본은 한국어이며 기존 저장도 한국어로 이어집니다. 선택한 언어는 기기에 저장되어 재접속·업데이트·오프라인에서도 유지됩니다. 플레이 중 바꿔도 판을 초기화하거나 새로고침하지 않으며 선택한 식물·자원·진행을 유지합니다.

메뉴, 도움말, 스테이지·팁, 캐릭터 이름·능력, 잠금·획득, 승패, 저장·오프라인·업데이트 안내와 접근성 레이블을 함께 전환합니다. 영어 이름은 **Sunbell, Peabud, Acorn Guard, Frostbloom, Burstbud, Twinpod, Thornleaf, Pumpkin Lobber, Sunlantern Tree, Ironleaf Fort**입니다. 문서 언어와 브라우저 제목도 바뀝니다. 설치 매니페스트의 앱 이름·아이콘은 정적이므로 홈 화면 설치 이름은 기본적으로 **정원 수비대**이며 설치 과정에서 이름을 바꿀 수 있습니다.

1. **함께할 식물 고르기**: 시작 전에 해당 정원에서 해금된 식물 중 **1~6종, 10단계에서는 최대 8종**을 고릅니다. 선택한 카드를 다시 누르면 뺄 수 있습니다. 전투에서는 고른 식물만 큰 카드로 표시하며 7~8종은 카드 목록만 스크롤합니다. 구버전에서 이미 시작한 판은 기존 카드 목록을 유지합니다.
2. **햇빛 모으기**: 노란 햇빛을 누르거나 **손가락으로 쓸고 지나가면** 25를 얻습니다. 해등나무의 **50 표시 햇빛**은 50을 줍니다. 놓친 햇빛도 8초 후 자동으로 모입니다. 보드를 드래그해도 게임 화면은 움직이지 않습니다.
3. **식물 배치와 방어**: 왼쪽 식물을 고른 뒤 빈 정원 칸을 누릅니다. 키보드에서는 Tab과 Enter로 조작합니다. **배치 성공 후에는 선택이 해제**되고, 선택한 카드를 다시 눌러도 취소됩니다. 세 번의 무리를 막으면 별도 안내 문구 없이 **3초 후** 축하 화면이 나옵니다. 좀비가 왼쪽 끝을 통과하면 하트 하나를 잃고, 모두 잃으면 다시 도전합니다.

게임 시작·재시작·이어서 하기에서는 아무 식물도 선택하지 않습니다. 선택이 없으면 땅을 눌러도 심지 않으며, 햇빛 탭은 **수집만** 합니다. 햇빛이 자동 수집되어 누르는 도중 사라지더라도 같은 포인터 동작으로 아래 땅에 식물이 심어지지 않도록 보호합니다. 배치 실패 시에는 선택을 유지해 다른 칸을 고를 수 있습니다.

| 처음 사용할 정원 | 식물 | 햇빛 | 하는 일 |
|---:|---|---:|---|
| 1 | 콩별이 | 125 | 같은 줄 앞쪽으로 완두콩 공격 |

| 4 | 방울폭탄 | 125 | 심은 뒤 1초 후 주변과 이웃 줄에 범위 공격 |
| 5 | 쌍콩이 | 225 | 2초마다 위·아래 꼬투리에서 0.2초 간격으로 18 피해의 콩 두 발 |
| 6 | 가시풀 | 200 | 2.8초마다 26 피해의 가시, 같은 줄 최대 3명 관통 |

**콩별이와 햇살봉은 1단계부터 기본 해금**되어 함께 사용할 수 있습니다. **1~8단계 최초 클리어마다** 도토리벽 → 서리초 → 방울폭탄 → 쌍콩이 → 가시풀 → 호박포 → 해등나무 → 철잎보루를 한 종류씩 얻어 다음 정원부터 사용합니다. 최초 획득 화면에는 새 식물 그림·이름·능력·햇빛 비용·사용 가능한 정원을 표시하며, 이미 깬 정원을 다시 깨면 최초 획득 안내를 반복하지 않습니다.

**사용 가능한 식물은 플레이 중인 정원 번호 기준**입니다. 예를 들어 10단계까지 열었어도 1단계 재도전에서는 콩별이와 햇살봉을 사용할 수 있습니다. 새 게임·재시작·이전 정원 재도전·기존 저장 이어하기 모두 같은 규칙을 적용합니다. 잠긴 카드와 정원 선택 화면에도 같은 해금 위치를 표시합니다.

잠옷좀비는 기본형, 젤리좀비는 튼튼한 느림보, 롤러좀비는 빠른 유형, 우산좀비는 우산이 있는 동안 추위에 강한 유형입니다. 처음부터 햇살봉으로 자원을 확보하고, 후반에는 도토리벽·서리초·방울폭탄을 함께 활용해 보세요.

**삽**을 누르고 식물을 선택하면 제거하고 가격의 절반을 돌려줍니다(소수점 버림). 삽 모드 진입 시 식물 선택도 해제합니다. 심은 식물 종류마다 다시 심기까지 짧은 대기 시간이 있습니다. 남은 하트 수가 별 기록이 되며, 이미 얻은 더 좋은 기록은 유지됩니다.

### v11 웨이브 조정

새 판은 첫 좀비가 **18초**에 등장합니다(이전 12초). 첫 무리의 수를 줄이고 등장 간격도 이전의 1.2배로 늘려 준비 시간을 줍니다. 두 번째 무리는 이전 간격의 0.75배, 마지막 무리는 0.3배로 빨라집니다. 무리 사이에는 7초의 추가 간격을 유지합니다.

전체 좀비 수는 이전보다 약 40% 늘리고(올림), 늘어난 적은 마지막 무리에 집중합니다. 예를 들어 1단계는 **2 / 3 / 7명**, 10단계는 **8 / 12 / 36명**입니다. 식물 비용·능력, 좀비 종류·체력·이동속도와 해금 규칙은 바꾸지 않았습니다.

**업데이트 전에 시작한 판은 기존 등장 시간과 남은 수를 그대로 유지**합니다. 새 정원 시작·재시작부터 새 난이도를 적용하며 별·열린 정원·언어·진행 기록은 초기화하지 않습니다. 아래의 v10 전략 비교 수치는 이전 등장 규칙의 기록입니다.

### v12 피격·장비 탈락

우산좀비는 누적 **65 피해**(남은 체력 110 이하)를 받으면 우산을 한 번 떨어뜨립니다. 노란 외투와 원래 얼굴은 유지하고, 이후 이동속도는 일반 좀비와 같은 17, 서리 감속 배율은 0.48로 바뀝니다(우산 보유 시 18 / 0.8). 체력을 다시 채우거나 다른 적으로 교체하지 않습니다.

다른 좀비는 체력 절반 이하에서 잠옷·젤리옷·스케이트 재킷 조각이 흩어집니다. 이 효과는 전투 능력을 바꾸지 않습니다. 우산과 옷 조각은 회전하며 떨어진 뒤 사라지고, 일시 정지·백그라운드에서는 함께 멈춥니다. 탈락 여부는 진행 저장에 남아 복구 뒤 우산이 다시 생기거나 같은 효과가 반복되지 않습니다. 피·신체 훼손 표현이나 외부 이미지 요청은 없습니다.

### v13 전투 효과음

홈의 **소리 꺼짐 / Sound off** 버튼을 누르면 소리를 켤 수 있습니다. 처음 방문에서는 꺼져 있고 기존 선택을 유지합니다. 잠옷좀비는 낮고 느슨한 울음, 젤리좀비는 말랑한 떨림, 우산좀비는 조금 높은 울음, 롤러좀비는 두 번 스치는 **슉슉** 소리를 냅니다. 이동 중인 적만 간헐적으로 소리를 내고 피격음도 종류별로 다릅니다. 서리 피격·식물을 무는 소리·폭발·옷이나 우산 탈락도 연결했습니다.

동시 음원은 최대 6개, 피격음은 최소 0.12초 간격, 보행음은 전체 최소 1.4초 및 같은 종류 6초 간격(롤러 3.4초)으로 제한합니다. 낮은 출력과 컴프레서로 겹치는 소리를 억제하지만 실제 크기는 기기 음량에 따라 달라집니다. 정지·백그라운드·음소거 때 재생 중인 소리까지 끊고, 다시 시작할 때 밀린 소리를 몰아서 재생하지 않습니다.

Web Audio로 직접 합성하므로 외부 음원·CDN·추가 다운로드 없이 오프라인에서도 동작합니다. Safari에서는 사용자 탭 뒤 소리가 활성화됩니다. 실제 iPhone/iPad 스피커의 음량과 음색은 실기기에서 최종 확인이 필요합니다.

### v14 모바일 조작·출전 식물 선택

1단계의 새 판은 가운데 세 줄뿐 아니라 **다섯 줄 모두**에서 좀비가 등장합니다. 기존 진행 중인 판의 등장 순서는 보존하고 새 정원·재시작부터 적용합니다. 승리 기록과 해금은 즉시 저장하지만 결과 화면만 잠시 늦게 표시합니다(v15부터 안내 문구 없이 **화면에 보이는 시간으로 3초 후**). 그동안 쓰러짐·탈락 효과를 표시하고 전투는 더 진행하지 않습니다.

햇빛은 탭·키보드뿐 아니라 누른 채 쓸어 모을 수 있습니다. 빠른 움직임도 두 포인터 위치 사이의 경로로 검사하며, 햇빛 수집·드래그·취소·다중 포인터는 아래 땅의 오배치로 이어지지 않게 합니다. 전투 화면은 고정하고, 식물 선택 창의 목록과 구버전 저장의 카드 목록만 필요한 부분에서 스크롤합니다.

새 판은 해금된 식물 중 최대 6종을 선택합니다(v15부터 10단계는 8종). 작은 화면의 전투 카드는 **2열**, 그림은 **56px**, 일반 큰 화면에서는 **72px**입니다. 여섯 장은 스크롤 없이 표시하고, 7~8장은 그림을 줄이지 않고 카드 영역만 스크롤합니다. 선택 순서와 구성은 진행 중인 판에 저장합니다. 구버전 판에는 임의로 선택 제한을 씌우지 않으며 재시작할 때 새로 고릅니다.

세로 기기에서도 홈·식물 선택·전투·안내 창을 자동으로 가로형으로 표시하고 터치 좌표도 맞춥니다. **기기의 OS 방향을 강제로 잠그는 기능은 아닙니다.** iPhone Safari의 방향 잠금 제한을 피하기 위해 게임 화면 자체를 회전합니다. 방향 전환만으로 게임이나 소리를 멈추지 않으며, 다른 앱으로 이동하면 기존처럼 정지합니다.

### v15 초반 완화·웨이브 표시·다시하기·음량·8종 선택

새 판의 첫 좀비는 **25초**에 나옵니다. 1단계는 초반 **1명**, 나머지 단계도 **2명만 14초 간격**으로 나오며 모두 기본 잠옷좀비입니다. **55초부터 중간 무리**, **90초 이후 최종 무리**가 시작됩니다. 중간 무리는 전체의 약 25%(올림), 최종 무리는 남은 절반 이상을 짧은 간격으로 보냅니다. 전체 좀비 수와 식물·좀비 능력치는 그대로이며, 후반 정원도 초반부터 여러 적이 몰리지 않게 했습니다. 예를 들어 1단계는 **1 / 3 / 8명**, 10단계는 **2 / 14 / 40명**입니다.

보드 아래 진행 바는 **해당 판의 등장 시간표**에 따라 채워지고, 중간·최종 무리 시작 지점에 표시가 있습니다. 정지·백그라운드에서는 멈추고 저장 복구 시 같은 위치에서 이어집니다. 100%는 모든 좀비의 **등장 완료**이며 승리를 뜻하지 않습니다. 아직 등장하지 않은 적과 보드에 남은 적을 합친 **남은 좀비 수**를 함께 보여 줍니다. 작은 화면에서는 기존 하단 설명 대신 진행 바와 남은 수를 우선 표시하며 카드·칸의 44px 터치 영역을 유지합니다.

홈의 **정원 선택 · 다시하기 / Choose / replay**에서 완료한 정원의 **다시하기 / Replay**를 누르면 처음부터 재도전할 수 있습니다. 진행 중인 다른 판이 있다면 교체 전에 확인하고 출전 식물을 다시 고릅니다. **별·열린 정원·언어·소리 설정은 지우지 않습니다.** 현재 판만 시작 자원·빈 보드·새 등장 규칙으로 초기화합니다. 기존 판의 이어하기는 이전 등장 시간표를 그대로 유지하므로 새 난이도를 바로 보려면 다시 시작하세요.

승리 후에는 ‘마지막 장면을 감상해요’ 같은 안내 없이 **3초** 기다린 뒤 결과를 표시합니다. 다른 앱으로 이동한 시간은 대기 시간에 포함하지 않습니다.

홈과 게임 상단의 **⚙ 소리 설정 / Sound settings**에서 켜기·끄기, **0~100% 음량**, **미리 듣기 / Preview sound**를 사용할 수 있습니다. 기존의 소리 켜짐/꺼짐 선택은 보존하고, 음량이 없는 이전 저장은 **45%**로 읽어 기존 출력을 유지합니다. 0%는 음소거, 음량을 올리면 효과음이 켜집니다. 100%는 이전 최대 출력보다 여유가 있고 동시 음원 제한과 컴프레서는 유지합니다. 설정 창에서는 전투를 멈추며 완료 후 일시 정지 화면의 계속하기로 돌아갑니다. 음량도 업데이트·오프라인 재접속에 유지합니다. 기기의 미디어 음량·무음 모드·Bluetooth 출력은 웹 게임에서 강제로 바꿀 수 없습니다.

**10단계는 최대 8종**을 고를 수 있습니다. 1~9단계는 기존처럼 최대 6종이며, 이미 저장한 6종 팀은 임의로 바꾸지 않습니다. 재시작할 때 새로 고를 수 있고, 7~8종 팀은 가로·자동 회전 화면 모두 큰 카드 목록만 스크롤합니다.

초반 준비 시간이 늘어났으므로 아래의 과거 전략별 승패 비교를 v15의 난이도 보장으로 해석하지 마세요. 현재 규칙도 실제 비용·쿨다운과 정원별 출전 제한으로 열 정원 통과를 검사합니다.

### 새 다섯 식물의 역할과 제한

- **쌍콩이**: 체력 120, 재배치 9초. 두 발은 동시에 나오거나 한 발에 합쳐지지 않습니다. 두 번째 발의 예약은 식물에 저장되어 정지·복구 뒤 이어지고, 식물이 죽거나 삽으로 제거되면 함께 사라집니다. 평균 피해는 초당 18로 콩별이의 11.25보다 높지만, 비용당 피해는 조금 낮아 한 칸의 화력을 늘리는 선택입니다.
- **가시풀**: 체력 100, 재배치 9초. 관통한 적 ID를 저장하므로 같은 적에 중복 피해를 주지 않으며 세 명 뒤에는 소멸합니다. 한 명에 대한 초당 피해는 약 9.29로 콩별이보다 낮고, 여러 적이 같은 줄에 모였을 때 유리합니다.
- **호박포**: 체력 130, 재배치 10초. 발사 순간 가장 앞선 같은 줄 적의 위치를 착지점으로 정합니다. 비행은 거리별 0.45~1.6초이며 적을 추적하지 않습니다. **착지 때만** 반경 115 게임 좌표(한 칸 100)의 원 안에 피해를 줍니다. 비행 중·폭발 그림에는 추가 피해가 없습니다. 방울폭탄의 반경 175·피해 340보다 좁고 약하지만 반복 공격합니다.
- **해등나무**: 체력 140, 재배치 10초. 첫 생산까지 10초가 걸리므로 비용 50·첫 생산 6초인 햇살봉보다 초반 투자가 큽니다. 대신 한 칸에서 초당 평균 5 햇빛을 생산합니다(햇살봉은 3.125).
- **철잎보루**: 공격은 없습니다. 체력 650·비용 75·재배치 8초인 도토리벽보다 두 배 비싸고 배치 간격도 길지만, 체력은 1500으로 더 오래 버팁니다. 체력 35% 이하에서는 손상된 잎 프레임을 사용합니다.

v10 확장에서는 **기존 식물·좀비의 능력치와 10개 정원의 등장 규칙을 변경하지 않았습니다.** 기존 다섯 식물만의 혼합 전략도 계속 통과합니다. 새 식물 조합은 단일 적 비용 효율과 초기 자원 투자가 다르므로 무조건 빠르거나 쉬운 상위 호환으로 만들지 않았습니다.

새 식물을 사용하는 자동 전략에서도 자원·쿨다운 보정 없이 열 정원 모두 하트 3개로 통과했습니다. 5단계에서는 쌍콩이를 첫 식물로 배치해 시작합니다. 전체 식물 손실은 기존 조합 21개·확장 조합 26개, 최장 진행은 각각 129.4초·153.4초였습니다. 특정 배치 규칙의 비교이지 모든 조합이 같은 난이도라는 보장은 아닙니다.

### 난이도 조정

| 항목 | 이전 | 현재 |
|---|---:|---:|
| 콩별이 비용 | 100 | 125 |
| 콩별이 1발 피해 | 22 | 18 |
| 콩별이 발사 간격 | 1.25초 | 1.6초 |
| 콩별이 평균 초당 피해 | 17.6 | 11.25 (약 36% 감소) |
| 콩별이 다시 심기 대기 | 3초 | 6초 |
| 젤리좀비 체력 / 속도 | 300 / 12 | 340 / 13 |
| 롤러좀비 체력 / 속도 | 85 / 29 | 95 / 31 |

좀비 속도 단위는 게임 좌표/초입니다. 기본 좀비와 스테이지별 등장 수·등장 간격은 그대로 두어 초반 학습 난이도를 과도하게 높이지 않았습니다.

`tests\helpers\strategy.mjs`의 동일한 판단 규칙(최대 초당 1회 배치, 실제 비용·쿨다운 준수)으로 밸런스 변경 전후를 비교했습니다. ‘콩별이 중심’은 공격 식물을 콩별이만 사용하고, 햇살봉도 함께 사용하는 전략입니다. ‘혼합’은 가까운 적에 도토리벽, 느리게 할 서리초, 밀집한 적에 방울폭탄을 사용합니다.

| 비교 전략 | 변경 전 | 변경 후 |
|---|---|---|
| 콩별이 중심 | 10개 모두 하트 3개, 식물 손실 0 | 9개 통과, 8·9단계 하트 2개, 10단계 패배 |
| 혼합 | 10개 모두 하트 3개 | 새 해금 규칙으로 10개 모두 하트 3개 |

위 표는 최초 밸런스 개정 전후의 비교입니다. 당시 혼합 전략의 식물 손실은 합계 2개에서 20개로 늘었습니다. 현재의 앞당긴 해금 순서에서는 혼합 전략으로 10개 정원 모두 하트 3개를 유지하고 식물 손실은 합계 21개입니다. 이는 정해진 전략의 회귀 검사이며, 모든 콩별이 전략의 불가능성이나 실제 어린이 플레이 난이도를 보장하는 것은 아닙니다.

햇살봉 기본 해금·보상 순서·애니메이션 수정에서는 비용·공격력·쿨다운·좀비 능력치·등장 규칙을 바꾸지 않았습니다. 현재 혼합 전략의 1단계는 75.7초, 3단계는 102.0초이며 가장 긴 정원은 129.4초입니다. 승인된 새 해금 순서를 변경 전후 엔진에 동일하게 적용한 비교에서는 전략 2종×정원 10개의 전투 상태·자원·배치 시점이 모두 일치하여 시각 변경 자체의 전투 영향을 확인했습니다.

### 현재 그래픽의 범위

사용자가 승인한 만화풍 생성 원화를 바탕으로 **식물 10종과 좀비 4종 전체를 프레임 애니메이션**으로 적용했습니다. 캐릭터마다 4열×3행, 총 **14종 168프레임**을 사용합니다.

| 캐릭터 | 1행 | 2행 | 3행 |
|---|---|---|---|
| 콩별이 | 대기 | 발사 준비·압축·발사·복귀 | 피격 |
| 햇살봉 | 대기 | 햇빛 생성 | 피격 |
| 도토리벽 | 대기 | 피격 방어 | 체력 35% 이하 균열 |
| 서리초 | 대기 | 발사 준비·발사·복귀 | 피격 |
| 방울폭탄 | 대기 | 폭발 준비 | 폭발·흩어지는 잎 |
| 쌍콩이 | 대기 | 위 꼬투리 발사·회복·아래 발사·복귀 | 피격 |
| 가시풀·호박포 | 대기 | 발사 준비·발사·복귀 | 피격 |
| 해등나무 | 대기 | 강화 햇빛 생성 | 피격 |
| 철잎보루 | 대기 | 피격 방어 | 체력 35% 이하 잎 손상 |
| 잠옷·젤리·롤러·우산좀비 | 이동 | 공격 | 쓰러짐 |

콩별이·서리초의 발사와 햇살봉의 생성 프레임을 실제 생성 시점에 맞췄습니다. 새 적이 갑자기 나타나면 애니메이션을 기다리느라 발사를 늦추지 않습니다. 연속 피격도 매 틱 처음으로 되감지 않습니다. 죽은 좀비는 즉시 전투에서 제거하고 0.88초의 쓰러짐 효과만 별도로 표시하므로 추가 공격은 없습니다. 마지막 적을 잡은 후 결과 창만 3초 늦게 표시합니다. 방울폭탄은 기존처럼 1초 뒤 한 번만 피해를 주고 제거되며, 이후 폭발 그림만 별도로 재생합니다. 일시 정지·백그라운드에서는 재생도 멈추며, 진행 중인 발사·생성·피격·공격 시점은 저장하고 복원합니다. 사망·폭발의 일회성 효과는 저장하지 않습니다.

게임 보드, 식물 카드, 시작·도움말·획득 화면과 앱 아이콘에 같은 새 아트를 사용합니다. 기존 캐릭터 벡터 시안은 제거했습니다. 과도한 공포나 잔혹 표현은 넣지 않았습니다.

완두콩은 초록색 유기적 형태와 명암·하이라이트, 서리초의 발사체는 청백색 얼음 결정으로 그립니다. 기존 두 식물의 발사체 규칙은 유지합니다. 쌍콩이는 위·아래 꼬투리의 서로 다른 높이에서 콩을 쏘고, 가시풀은 자주색 끝과 초록 밑동의 가시를 쏩니다. 호박포는 작은 주황 호박탄을 잎컵에서 포물선으로 던지고 착지 범위·씨앗 파편을 보여 줍니다. 햇살봉·해등나무는 황금빛 햇빛, 방울폭탄은 주황 폭발과 잎 조각을 사용하고 도토리벽·철잎보루에는 공격을 추가하지 않습니다.

하늘에서 떨어지는 햇빛과 생산 식물이 만든 햇빛 모두 밝은 코어·가장자리 명암·하이라이트·태양 빛살을 사용합니다. 빛살이 천천히 회전하고 광채가 부드럽게 변하며 빠른 점멸은 없습니다. 광채 레이어는 재사용하고 게임 시간으로 움직여 정지·백그라운드 전환 때 함께 멈춥니다. 기존 48px 터치 타깃, 하늘·햇살봉의 햇빛 25, 8초 자동 수집과 오배치 방지는 그대로입니다. 해등나무 토큰에는 50을 표시하고 접근성 레이블에도 같은 값을 제공합니다.

원본 RGBA 시트는 비공개 작업 폴더 `art-source`에 보관하고, 게임에는 정렬·축소한 `assets\sprites`의 PNG 14장만 사용합니다. 각 1280×672픽셀, 합계 약 6.4 MiB입니다. 실제 알파를 사용하고 크로마키 처리는 하지 않았습니다. 약한 반투명 잔여색을 정리한 뒤 캐릭터별 고정 배율(0.58~0.66)을 적용하고 뿌리·발 접지점을 정렬했습니다. 공격·쓰러짐의 크기 변화는 유지하며 프레임마다 제각각 확대하지 않습니다. 원본의 실제 빈 영역으로 행별 행·열 경계를 정해 발·스케이트·우산 잘림을 방지하고, 새 가시풀·호박포의 격자 경계를 넘은 포즈도 개별 열 경계로 보존했습니다. 햇살봉·방울폭탄의 방향이 뒤집힌 대기 그림은 반전해 맞췄습니다.

기존 아홉 캐릭터의 프레임 연결 당시에는 직전 엔진과 동일한 전략 2종×정원 10개를 실행하여 최종 전투 상태·자원·배치 시점이 모두 일치함을 확인했습니다. 이후 새 다섯 식물에만 위의 새 능력을 추가했습니다. 생성된 4프레임 시트의 움직임을 사용하는 방식이며, 손으로 보정한 다프레임 애니메이션과 같은 유연함을 보장하지는 않습니다.

## 아이폰·아이패드에 설치하기

공개 게임 주소를 다른 기기의 Safari에서 열 수 있습니다. 로그인이나 앱스토어 설치는 필요 없습니다. GitHub Pages의 HTTPS를 사용하며 별도 유료 호스팅이나 도메인은 필요 없습니다.

로컬 `127.0.0.1`과 공개 주소는 서로 다른 저장 공간입니다. **기존 로컬 진행은 공개 주소로 자동 이동하지 않습니다.** 기존 로컬 기록을 지우지는 않으며 공개 주소에서는 새로 시작합니다.

### 1. HTTPS 주소 준비

일반 정적 웹 호스팅에 다음 명령으로 만든 **`dist` 폴더의 내용만** 올리면 됩니다. 별도 API나 데이터베이스, Node.js 서버 운영은 필요 없습니다.

```powershell
npm run build
```

`dist`에는 HTML, CSS, JavaScript, 매니페스트, 서비스 워커, PNG 아이콘과 가공된 캐릭터 프레임 시트만 담깁니다. `art-source`, `node_modules`, 테스트 코드, 개발 서버를 웹사이트에 배포하지 마세요. 공개 저장소의 `main`에 푸시하면 `.github/workflows/pages.yml`이 단위 검사와 정적 빌드를 수행하고 `dist`만 GitHub Pages에 배포합니다.

배포 조건:

- 신뢰할 수 있는 인증서의 **HTTPS** 주소여야 합니다.
- 주소의 루트 또는 하위 폴더에 **파일 구조 그대로** 배포합니다. 하위 폴더 주소는 끝에 `/`를 붙입니다.
- `.js`는 JavaScript, `.webmanifest`는 `application/manifest+json`, `.png`는 `image/png`로 제공합니다.
- `sw.js`는 리다이렉트·로그인 화면 없이 제공하고, `Cache-Control: no-cache`를 권장합니다.
- 런타임 파일을 누락하지 마세요. 하나라도 저장 실패하면 ‘오프라인 준비 완료’를 표시하지 않습니다.
- 로컬 컴퓨터의 `localhost`·`127.0.0.1`은 **아이폰에서 이 컴퓨터를 가리키지 않습니다**. LAN의 일반 HTTP 주소로 여는 것만으로는 iOS 오프라인 설치를 검증할 수 없습니다.
- 개인용으로 제한하고 싶다면 호스팅 접근 정책도 별도로 검토하세요. 게임 자체는 로그인이나 온라인 DRM을 포함하지 않습니다.

### 2. Safari 홈 화면에 추가

1. 아이폰·아이패드의 Safari에서 배포한 HTTPS 주소를 엽니다.
2. 자동으로 표시되는 가로형 화면 아래 **‘오프라인 준비 완료 · 이 기기에 저장됨’**(영어: **Offline ready · Saved on this device**)을 확인합니다.
3. Safari **공유 → 홈 화면에 추가 → 추가**(**Share → Add to Home Screen → Add**)를 누릅니다. ‘웹 앱으로 열기’(**Open as Web App**) 옵션이 보이면 켭니다.
4. 홈 화면의 ‘정원 수비대’ 아이콘으로 실행합니다. **그 창에서도 온라인 상태로 ‘오프라인 준비 완료’를 다시 확인**합니다.
5. 비행기 모드로 바꾸고 게임을 완전히 닫았다가 홈 화면 아이콘으로 다시 엽니다. 시작과 이어서 하기가 되는지 확인합니다.

Safari와 홈 화면 웹 앱은 OS 버전에 따라 저장 공간을 다르게 취급할 수 있습니다. 설치 전 Safari 진행 기록이 홈 화면 앱으로 옮겨진다고 보장하지 않습니다. 홈 화면 앱 안에서 처음부터 플레이하는 것을 권장합니다.

대상은 최신 iOS/iPadOS Safari이며, 사용 API 기준 **iOS/iPadOS 16.4 이상을 권장**합니다. 오래된 브라우저 지원을 위한 폴리필은 넣지 않았습니다. iOS의 방향 잠금과 관계없이 세로 뷰포트에서는 게임 UI 자체를 90도 회전해 가로형으로 표시합니다.

## 저장과 오프라인 동작

- 진행 데이터: `localStorage`의 `garden-guardians-save-v1`
- 열린 정원·최고 별·소리·안내 설정과 **진행 중인 판 1개**를 저장합니다.
- 진행 중 약 3초마다, 심기·삽 사용·일시 정지·결과 처리·페이지 이탈 시 저장합니다.
- 강제 종료 직전에는 마지막 약 3초의 진행이 저장되지 않을 수 있습니다.
- 다른 앱으로 이동하면 자동 정지합니다. 돌아와서 **계속하기**를 눌러야 재개됩니다. 방향 전환은 화면 배치만 바꾸고 게임을 계속합니다. 닫힌 게임이 오프라인 동안 혼자 진행되지는 않습니다.
- 새 판의 출전 식물 `loadout`과 등장 규칙 `pacingVersion: 4`를 저장합니다. 이전 판의 선택 제한 없음·가운데 세 줄 등장·이전 등장 시간 등 기존 규칙은 그 판이 끝날 때까지 보존합니다.
- 새 정원을 시작하면 진행 중인 판만 바뀝니다. 열린 정원과 최고 별은 유지됩니다.
- 구버전 저장 키와 진행 데이터는 유지합니다. 현재 판은 `rulesVersion: 3`으로 읽고, 기존 다섯 식물의 쿨다운에 새 다섯 식물의 대기시간 0만 보강합니다. 기존 별·해금·언어·이미 심은 식물·자원·기존 쿨다운은 보존합니다. 가장 오래된 밸런스 개정 전 저장의 콩만 기존에 정한 피해량으로 이관합니다. 구버전에서 먼저 심은 잠긴 식물도 그 판에서는 남지만 새로 추가할 수 없으며, 재시작하면 해당 정원의 정상 해금 구성을 적용합니다.
- 두 번째 콩 발사 예약, 관통탄이 맞힌 적 목록, 호박탄의 고정 착지점·비행 경과, 50 햇빛도 저장하고 검증합니다. 정지·재접속·업데이트 때문에 예약 공격이 중복되거나 제거된 식물이 발사하지 않게 합니다.
- 햇살봉 기본 해금과 앞당긴 해금 단계는 저장 초기화나 새 판 시작 없이 적용됩니다. 기존 1단계 저장에서도 햇살봉, 2단계에서 도토리벽, 3단계에서 서리초, 4단계에서 방울폭탄을 바로 추가로 심을 수 있습니다. 별·열린 정원·보유 햇빛·기존 쿨다운 등 진행 상태는 그대로 유지합니다.
- 저장 오류나 손상된 데이터는 화면에 안내하고, 오류를 숨기지 않습니다. 저장이 차단된 상태에서도 현재 창에서 플레이할 수 있지만 재접속 복원은 보장되지 않습니다.
- 서비스 워커는 필수 자원을 **일괄 저장**한 뒤 준비 완료를 표시합니다. 누락 시 온라인에서 **다시 저장** 버튼으로 복구할 수 있습니다.
- 캐릭터 시트 14장도 모두 필수 캐시 대상입니다. 그림을 불러오지 못하면 게임 시작을 막고 오류와 **그림 다시 불러오기** 버튼을 표시합니다. 구형 도형으로 몰래 대체하지 않습니다.
- 기기 간 자동 동기화는 없습니다. Safari 사이트 데이터 삭제, 비공개 브라우징, 앱 제거, OS 저장 공간 정리로 기록이나 캐시가 사라질 수 있습니다. 오프라인 보존은 OS 정책을 넘어 보장할 수 없습니다.
- 같은 기기에서는 한 창에서 플레이하는 것을 권장합니다. 여러 창이 동시에 진행 데이터를 수정하는 것은 지원하지 않습니다.

### 업데이트 배포

현재 오프라인 캐시는 `v15`이며 처음 화면 아래에 **화면 v15 / Version v15**을 표시합니다. 런타임 파일이 바뀌면 `sw.js`의 캐시 버전(`CACHE`)과 `index.html`의 화면 버전을 함께 바꾼 뒤 전체 `dist`를 배포하세요.

v7부터 새 버전이 모두 저장되면 처음 화면과 일시 정지 메뉴에 **저장하고 업데이트 / Save and update** 버튼이 나타납니다. 누르면 진행과 언어 설정을 저장하고 새 서비스 워커를 활성화한 다음 새로고침합니다. 저장에 실패하면 업데이트를 중단합니다. **플레이 중이나 다른 탭을 강제로 새로고침하지 않습니다.** 이미 내려받은 업데이트는 오프라인에서도 적용할 수 있습니다. 다른 탭이 먼저 업데이트했다면 이 탭에서도 버튼을 눌러 새 화면을 불러옵니다.

**v5/v6에서 처음 전환할 때:** 이 버전에는 업데이트 버튼이 없습니다. 단순 새로고침은 기존 서비스 워커 때문에 구버전을 다시 표시할 수 있습니다. 온라인에서 같은 주소의 게임 탭과 설치 앱 창을 모두 닫고 다시 열어 주세요. 사이트 데이터나 저장을 삭제할 필요가 없습니다. 새 업데이트를 다운로드하려면 온라인 연결이 필요하며 저장 스키마가 바뀌면 별도 마이그레이션이 필요합니다.

## 개발과 자동 검증

```powershell
# 게임 규칙·저장·프레임 상태·모든 스테이지 통과 검사 (외부 패키지 불필요)
npm test

# 브라우저 자동화 도구 준비
npm ci
npx playwright install chromium webkit

# Chromium + WebKit 터치·저장·오프라인 검사
npm run test:browser

# 배포 파일 만들기
npm run build
```

Playwright가 로컬 서버를 자동으로 시작합니다. 이미 `npm start`로 실행했다면 그 서버를 재사용합니다. 의존성 다운로드와 브라우저 설치에는 개발 시 인터넷이 필요하지만, 게임 실행에는 필요 없습니다.

그림 합성은 `src\art.js`, 프레임 선택·로딩은 `src\sprites.js`, 규칙·정원 구성은 `src\engine.js`, 화면·입력·수명 주기는 `src\app.js`, 번역 매핑과 동적 문구는 `src\i18n.js`에 있습니다. 캐릭터 내부 ID와 게임 규칙 데이터는 번역하지 않습니다. 번역은 표시 계층에서 적용하고 원문을 유지해 열린 안내 창도 이벤트 연결을 잃지 않고 전환합니다. 앱 아이콘을 PNG로 다시 만들려면 로컬 서버가 실행 중인 상태에서 `npm run icons`를 사용합니다. 아이콘 생성에도 외부 이미지 서비스는 사용하지 않습니다.

원본 시트에서 게임 자산을 다시 가공할 때만 Python 3과 Pillow가 필요합니다. 일반 게임 실행·빌드에는 필요 없습니다. 원본 작업 이미지가 있는 로컬 `art-source`는 공개 저장소에서 제외했습니다. 아래 가공 명령은 해당 원본을 별도로 보유한 개발용 환경에서만 실행합니다.

```powershell
python -m pip install Pillow
python scripts\prepare-sprites.py
npm run icons
npm run build
```

가공 스크립트는 셀 경계의 잘림을 검사하고 정렬 근거를 `assets\sprites\alignment.json`에 남깁니다. 새 원화로 바꾸면 이 스크립트의 행 경계·뿌리/발 좌표도 원화에 맞게 확인해야 합니다. 외부 이미지 생성 서비스에 런타임 요청을 보내지 않습니다.

### 검증 범위와 한계

v15에서 단위 검사 **70개**, Chromium·WebKit 브라우저 검사 **113개 통과·기존 도구 제한 1개 제외**를 확인했습니다. 초반 1~2명과 단계별 시간표·진행 바, 이전 판의 시간표 유지, 기록 보존 재도전, 문구 없는 3초 결과 대기, 0~100% 실제 음량 파형과 미리 듣기·재개·오프라인 저장, 10단계 8종 선택·가로/회전 화면의 카드 스크롤·업데이트 보존을 포함합니다.

v14에서 단위 검사 **67개**, Chromium·WebKit 브라우저 검사 **97개**가 통과했습니다. 기존 WebKit 영구 프로필 제한에 해당하는 1개는 제외했습니다. 새 검사는 다섯 줄 등장·이전 등장 순서 보존, 최대 6종/최소 1종 선택과 저장, 2초 결과 지연과 백그라운드 제외, 빠른 햇빛 쓸기·키보드·취소·다중 포인터, 320×568·390×844 세로 화면의 가로형 터치 좌표와 회전 중 진행을 포함합니다. 자동 전략은 실제 자원·쿨다운으로 6종 이하의 팀을 사용해 열 정원 모두 통과했습니다.

자동 검사는 첫 시작 두 식물, 재시작·재도전·기존 저장, 1~8단계 최초 보상과 중복 방지, 10종 해금, 버전별 캐시 전환을 포함합니다. 한국어·영어 메뉴/획득/오류/접근성 문구, 플레이 중 전환, 언어 없는 구버전 저장, 다중 탭의 명시적 업데이트, 영어 설정·진행 보존과 저장·자산 다운로드 실패도 검사합니다. 테스트 서버를 실제로 종료한 뒤 양 엔진에서 새 식물·영어 설정을 유지한 오프라인 재실행을 확인했습니다. 두 발의 시간차·위아래 원점·죽거나 제거된 식물의 예약 취소·업데이트 중 예약 보존, 관통 중복 방지·3명 한도, 포물선 고정 착지점·범위 경계, 50 햇빛·생산 주기, 철잎보루 체력도 검사합니다.

배포 파일은 `npm run build`로 **29개(약 6.9 MiB)**를 만듭니다. 브라우저 검사는 선택 없음·배치 후 해제·카드 토글·햇빛 탭 및 자동 수집 중 오배치 방지·1~10단계 해금·이전 저장 이관까지 포함합니다. 568×320부터 1180×820까지 가로 화면에서 게임 칸·식물 선택·게임 상단 버튼의 터치 영역을 최소 44×44 CSS 픽셀로 검사합니다. 구버전 판은 스크롤로 카드 열 장에 접근하고, 새 판은 선택한 최대 여섯 장을 스크롤 없이 표시합니다. 실제 Chromium 터치 스와이프와 WebKit 포인터 드래그, 작은 가로 화면의 한국어·영어 최초 획득 카드와 진행 버튼 접근도 검사합니다.

추가로 168개 프레임의 픽셀 차이·투명 테두리·접지 정렬, 실제 Canvas의 이동·발사·생성·피격·방어·균열·폭발·공격·쓰러짐 프레임 사용, 정지 중 화면 불변, 화면 회전·저장 복구, 이미지 누락 오류·재시도를 검사했습니다. 완두콩·얼음의 구분과 기존 전투 좌표 불변, 햇빛 광채 변화·정지·수집도 검사했습니다. 새 다섯 식물이 나오는 568×320 영어 화면과 1024×768 한국어 화면을 캡처하고 짧은 전투 장면을 녹화했습니다. 이는 상태 확인용 장면이며 일반 플레이로 해금한 진행 영상은 아닙니다. 잔디 배경에서 검은 사각형·색 번짐·셀 잘림과 접지 위치를 확인했습니다.

자동 검증은 비용·쿨다운·공격·방어·서리·폭탄·햇빛 수집, 승패·다음 정원·재시작, 저장 복원·손상·저장 차단, 세로 회전, 캐시 누락·복구, 네트워크 차단 후 새로고침·새 창 실행을 포함합니다. 모든 정원은 자원이나 적 능력치를 바꾸지 않는 간단한 자동 전략으로 끝까지 통과하는지 검사합니다.

오프라인 검증에서는 테스트 전용 서버를 **실제로 종료**하고, 하위 폴더 주소에서 Chromium·WebKit의 새로고침과 새 창 실행을 확인합니다. Chromium은 네트워크 오프라인 설정까지 켠 상태에서 **브라우저 프로세스를 종료하고 같은 프로필로 재실행**하는 검사도 수행합니다. Windows Playwright WebKit은 네트워크 오프라인 에뮬레이션에서 내부 오류가 발생하고, 영구 프로필에서는 CacheStorage 쓰기가 비어 있는 현상이 재현되어 프로세스 재시작 검사는 명시적으로 건너뜁니다. WebKit에서 캐시 준비 실패를 성공으로 처리하거나 테스트를 느슨하게 바꾸지는 않았습니다.

**데스크톱 Chromium 및 Playwright WebKit 검증은 실제 iPhone/iPad Safari·홈 화면 앱 검증을 대신하지 않습니다.** 실제 기기를 연결해 검증하지 않았습니다. 백그라운드 전환 자동 검사는 페이지 수명 주기 이벤트를 재현한 것이며, 실제 iOS 앱 전환·메모리 회수·잠금 화면·오디오 하드웨어 동작은 실기기에서 최종 확인해야 합니다.

실기기 최종 확인 항목: 작은 아이폰의 Safari 도구막대·노치 안전 영역, 아이패드 화면 배치, 홈 화면 설치 후 비행기 모드 재실행, 3초 자동 저장과 이어서 하기, 효과음 켜기·끄기, 다른 앱이나 잠금 화면에서 돌아온 뒤 일시 정지 상태, 세로 회전과 화면 회전 잠금.
